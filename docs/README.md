This is the navigable index for OctoAcme's project management process documentation. Use it to quickly find the guide you need or to get a concise overview of how OctoAcme runs projects end to end.

## Project Management Process Summary

OctoAcme uses a structured, iterative project lifecycle that moves from initiation through planning, execution, release, and retrospective. Projects begin with a lightweight one-pager defining the problem, goals, success metrics, stakeholders, timeline, risks, and resource needs, and advance to planning once the business need is validated and stakeholders align on priority. Planning translates the approved initiative into a prioritized backlog, estimates, acceptance criteria, a Definition of Done, dependencies, milestones, and a release plan.

Execution is managed through a project board (Backlog, Ready, In Progress, In Review, QA, Done), small pull requests, code review, and CI-enforced automated testing and linting, supported by daily standups, weekly delivery syncs, and sprint/milestone demos. Throughout delivery, risks and dependencies are tracked in a risk register, assessed by impact and likelihood, assigned owners, and communicated via weekly PM/Product Manager syncs, monthly stakeholder updates, and escalation paths to the Project Manager, Product Lead, or sponsor when needed.

Releases require completed acceptance criteria, passing CI and security checks, release notes, a rollback plan, staging smoke tests, and post-deployment verification. After each sprint, release, milestone, or incident, teams hold a retrospective to capture what went well and what could improve, assigning a small number of owned, time-bound action items that are tracked through the ongoing PM cadence.

These processes rely on clearly defined personas: the Project Manager coordinates schedules, risk, and stakeholder communication; the Product Manager owns vision, backlog priorities, and success measures; Developers build, test, document, and review the software; and QA/Testing validates acceptance criteria and overall quality. Quality assurance is integrated throughout — not deferred to the end — via required code review, automated tests, linting, security scanning, and manual QA where needed.
